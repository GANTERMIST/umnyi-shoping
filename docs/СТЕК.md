# Стек «Умного Шопинга» и почему он такой

Документ для защиты: что выбрали, почему и от чего отказались. Отличия от плана из «Отчёта 2» тоже объяснены — их обязательно спросят.

## Коротко

| Слой | Выбрали | Вместо (что было в плане или рассматривали) |
|---|---|---|
| Ниша | Игры и игровые товары | Все товары (электроника, одежда…) |
| Данные | Открытые API: Plati.market, CheapShark, Steam | YML-фиды магазинов, парсинг сайтов |
| Бэкенд | Python 3.11, FastAPI, httpx, Pydantic | Django, Flask |
| База | SQLite + готовая схема PostgreSQL | PostgreSQL сразу |
| Фоновые задачи | Свой загрузчик `python -m app.loader` | Celery + Redis |
| Помощник | Своя нейросеть ShopNLU + ответы из данных | YandexGPT / GigaChat / Claude |
| Фронтенд | React 19 + TypeScript + Vite, PWA | Next.js, нативное приложение |
| Вход | PBKDF2 из стандартной библиотеки, сессия в HttpOnly-cookie | JWT, вход через соцсети |
| Запуск | `run.bat`, туннель localhost.run | Облачный сервер |

## 1. Почему игры, а не «все товары»

- **Данные.** Для обычных товаров нет открытых бесплатных API с ценами: маркетплейсы закрыты, партнёрские фиды дают по договору, парсинг ломается и не везде разрешён. Для игр есть открытые API: Plati.market — сотни продавцов с ценами в рублях и отзывами, CheapShark — официальные магазины, Steam — справочник игр.
- **Склейка.** У игры есть единый идентификатор — `appid` в Steam, по нему склеиваются предложения разных магазинов. У наушников или смартфона склейка по названию ошибается на комплектациях — это риск, записанный в отчёте 2.
- **Боль пользователя реальная.** Одна игра стоит 400 ₽ у продавца и 2 100 ₽ официально, но есть ключи, гифты, аккаунты, регионы и ненадёжные продавцы — без сервиса легко ошибиться.
- **Чем платим.** Критерий брифа «разные типы товаров» закрыт только частично: игры всех жанров, ключи, гифты, аккаунты и пополнения, но без электроники. Архитектура это не запрещает: новый источник — это ещё один метод в `app/sources.py`.

## 2. Источники данных: API, а не парсинг

| Источник | Что даёт | Почему он |
|---|---|---|
| Plati.market API | Цены в ₽, продавец, отзывы +/−, продажи, возвраты | Открытый, без ключа, крупнейшая площадка цифровых товаров в РФ |
| CheapShark API | Цены Steam, GOG, Humble, Fanatical, GMG, Epic и др. | Один запрос — все официальные магазины; закрывает критерий «≥ 3 площадок» |
| Steam Store API | Название, жанры, обложка, Metacritic, отзывы, список DLC | Справочник игр: по нему склеиваем и отсеиваем DLC и другие игры серии |

Отказались: **PlayerOK и FunPay** — API нет, только парсинг через Cloudflare и капчу; **GGsel** — партнёрский токен так и не выдали.
Надёжность: повторы запросов, кэш на 15 минут, при сбое Plati показываем сохранённые цены из базы с предупреждением, при ошибке загрузчик не затирает старую цену.

**Валюты.** Цены продавцов — в рублях, официальных магазинов — в долларах, и показываем их как есть, без пересчёта.
Курс ЦБ не отражает реальную цену покупки (комиссия зарубежной карты, конвертация банка), а пересчёт создавал бы
ложную точность. Поэтому рубли и доллары не сравниваются напрямую: бюджет в рублях применяется только к ценам продавцов,
в таблицах рублёвые цены идут первыми, а «Выгодно сегодня» строится по скидке в официальном магазине.

## 3. Бэкенд: Python + FastAPI

- Асинхронность нужна по сути задачи: на один поиск идут 5–20 запросов к внешним API (Plati, Steam, названия DLC, CheapShark). В FastAPI с httpx они выполняются параллельно, поэтому ответ укладывается в 10 секунд.
- Документация API (`/docs`, OpenAPI) строится автоматически из моделей Pydantic — фронтенд и бэкенд договариваются по ней, а не на словах.
- Pydantic проверяет все входные данные (почта, пароль, бюджет, фильтры) — это часть критерия «данные защищены».
- Python — это ещё и ML (PyTorch, numpy) в одном языке с бэкендом. Django для API на 20 методов тяжеловат, Flask не асинхронный «из коробки».

## 4. База: SQLite сейчас, PostgreSQL готов

- SQLite встроен в Python: не нужны сервер и Docker, проект запускается на любом ноутбуке одной командой — это важно для показа и проверки куратором.
- Нагрузка MVP — десятки игр и тысячи предложений, SQLite с ней справляется с запасом.
- Схема та же, что в отчёте 2 (product, store, offer, price_history, пользователи), и уже переписана для PostgreSQL в `db/schema.sql`. Переезд — смена слоя `app/db.py`, API не меняется.
- История цены пишется только при изменении — так график честный, а база не пухнет.

## 5. Фоновые задачи: свой загрузчик вместо Celery

- Задача одна: раз в сутки обновить цены по топу игр. Для неё Celery + Redis — это два лишних сервиса.
- `python -m app.loader --every-hours 24` идёт по чарту Steam и списку популярных игр, соблюдает лимит Steam (~200 запросов за 5 минут) паузами и при ошибке не затирает цену.
- Если понадобятся очереди и много задач — тогда уже Celery.

## 6. Помощник: своя модель, а не большой ИИ

План (отчёт 2) был «YandexGPT/GigaChat разбирает запрос и объясняет выбор». Сделали иначе:

- **Своя нейросеть ShopNLU** (BiGRU, ~836 тыс. параметров) разбирает запрос: намерение (купить / подобрать / отзывы / сравнить / вопрос), игра, тип товара, платформа, бюджет, жанр.
- **Ответ строится из данных** поиска и каталога. Модель физически не может выдумать цену или товар — ровно то требование, что было в отчёте 2 («модель не ищет товары сама»).
- Обучение — PyTorch на 30 000 сгенерированных запросах (размеченных данных про покупку игр нет), работа на сайте — чистый numpy: без GPU, без платного API, без интернета до ИИ-сервиса, ответ за доли секунды.
- Качество честно измерено: слепой тест (запросы, которых модель не видела) — 91% разборов целиком верны, 94% — намерение. Подробно — `docs/МОДЕЛЬ.md`.
- Минусы: модель понимает только темы, на которых училась; свободного разговора «как с ChatGPT» нет. Внешний Claude подключается по желанию (`ASSISTANT_ENGINE=claude`), но по умолчанию выключен.

## 7. Фронтенд: React + TypeScript + Vite

- План был Next.js «чтобы страницы товаров индексировались». Для учебного MVP поисковая индексация не нужна, а Next.js требует отдельный Node-сервер. Vite собирает статические файлы, которые раздаёт тот же FastAPI: один процесс, один порт, одна команда запуска.
- TypeScript: типы ответов API описаны один раз (`frontend/src/api.ts`), ошибки в полях ловятся при сборке.
- Зависимостей минимум — только react, react-dom, react-router-dom. График цены — свой SVG на 80 строк вместо библиотеки на сотни килобайт.
- **PWA** вместо нативного приложения: сайт ставится на телефон с иконкой и открывается как приложение. Закрывает пункт брифа «мобильное приложение» без второго кода под Android и iOS.

## 8. Безопасность

- Пароли — PBKDF2-SHA256 (200 000 итераций, соль 16 байт) из стандартной библиотеки: рекомендованный алгоритм, никаких лишних зависимостей.
- Сессия — случайный токен 256 бит; в базе хранится только его хэш, в браузере — cookie HttpOnly + SameSite=Lax (недоступна JavaScript, защищает от XSS-кражи и CSRF). JWT не взяли: его нельзя отозвать при выходе без дополнительного хранилища.
- После 5 неверных паролей вход блокируется на 15 минут; время ответа одинаковое для существующей и несуществующей почты.

## 9. Запуск и показ

- `run.bat` ставит зависимости, собирает фронтенд, при первом запуске загружает цены и открывает сайт.
- Для показа наружу — туннель localhost.run (Cloudflare Tunnel в нашей сети обрывался). Бесплатный адрес периодически меняется. Для постоянного адреса нужен сервер (VPS) или платный туннель.

## 10. Тесты

40 офлайн-тестов (`python -m unittest discover -s tests`): внешние API подменены, проверяются склейка и отсев DLC, фильтры, официальные магазины (цены в долларах, без смешивания с рублями), офлайн-режим, вход и блокировка, избранное с целевой ценой, оценки «помогла ли рекомендация», модель ShopNLU (включая совпадение numpy с PyTorch) и ответы помощника.
