# «Умный Шопинг» для игр — откуда брать данные и кто что делает

Итог разговора с Сеней (01.11.2026): делаем агрегатор цен на **игры и игровые товары**, данные берём **через официальные/открытые API, без парсинга**. Ниже — что проверено руками (curl + `sources_probe.py`), а не по памяти.

## 1. Источники: проверено

| Площадка | API | Ключ | Что отдаёт | Вердикт |

**Решение для MVP (2 магазина, как в отчёте 2):** Plati.market + GGsel (если дадут токен до ~08.11). Если GGsel молчит — второй источник CheapShark (сравнение «у перекупов в ₽» vs «официально в $»). Steam — не магазин, а справочник игр, к которому всё склеиваем.

## 2. Вопрос Сени «как сделать хвалят/ругают»

Решён без выжимки отзывов ИИ: у Plati в каждом предложении есть `count_positiveresponses`, `count_negativeresponses`, `count_returns`, `seller_rating`, `numsold`. Из этого считаем «надёжность продавца» и показываем как есть. Про саму игру — % положительных отзывов Steam (`appreviews`, если заработает с сервера) + metacritic из `appdetails`.

## 3. Какие данные нужны → в какие таблицы (схема из отчёта 2, поправки под игры)

| Таблица | Было | Для игр добавить |
|---|---|---|
| `product` | title, brand, model, gtin, specs, images | `steam_appid` (вместо gtin — по нему склеиваем), `genres`, `metacritic`, `steam_review_pct`, `is_dlc` |
| `store` | name, url, feed_url, rating | `api_type` (plati / ggsel / cheapshark) |
| `offer` | url, price, in_stock, delivery_days | `platform` (Steam/Xbox/PS/GOG/Epic), `kind` (ключ/гифт/аккаунт/пополнение), `region`, `seller_name`, `seller_rating`, `reviews_pos`, `reviews_neg`, `sold` |
| `price_history` | — | без изменений |

`delivery_days` для цифры не нужен — заменить на «моментально / вручную» (у Plati поле `sales_form`).

**Важно для поиска и фильтров:** «аккаунт» за 100 ₽ и «ключ» за 1300 ₽ — разные вещи. В выдаче обязательно фильтр **тип** (ключ / гифт / аккаунт) и **платформа**, по умолчанию — только ключи и гифты. Иначе «лучшая цена» всегда будет общим (шеренным) аккаунтом.

## 4. Склейка (Ф30) — как в прототипе

1. Ищем игру в Steam → получаем `steam_appid` и каноническое название.
2. Ищем то же название на Plati/GGsel.
3. Предложение относим к игре, если нормализованное название игры входит в название предложения **и** это не DLC (регэксп `dlc|дополнение|season pass…`, но не «+ все DLC / ultimate»).
4. Тип и платформу вытаскиваем регэкспами из названия (`offer_kind`, `offer_platform` в прототипе).
5. Отсекаем продавцов с < 5 положительных отзывов или негативом > 10 %.

Ошибки будут (название «Cyberpunk 2077 XBOX» vs PC) — поэтому платформа отдельным полем.

**Что уже видно на прогоне «elden ring»:** в выдачу попали DLC «Tarnished Pack» и **другая игра** «ELDEN RING NIGHTREIGN» — простое «название входит в название» не работает. Как чинить: брать из Steam `appdetails` список `dlc` и названия игр той же серии (`storesearch` возвращает их соседними результатами) и исключать предложения, где встречается более длинное совпадение с другим appid.

**Надёжность Plati:** API иногда не отвечает (SSL-handshake timeout, у нас 1 запрос из ~4 упал даже после 3 повторов). В Celery-задаче — повторы с паузой и не затирать старую цену, если запрос не прошёл.

## 6. Прототип

`sources_probe.py` (только стандартная библиотека Python, без ключей):

```
python sources_probe.py "cyberpunk 2077"
```

Печатает карточку игры из Steam и 3 самых дешёвых надёжных предложения Plati по каждому типу (ключ / гифт / аккаунт) с платформой и отзывами.
